## Prewarm at launch

You can prewarm the GPU device and fonts at launch, so the first `<Canvas>`
mounts faster.

### Android

```kotlin title="MainApplication.kt"
import com.margelo.nitro.tgfx.Tgfx

override fun onCreate() {
  super.onCreate()
  Tgfx.prewarm()
  loadReactNative(this)
}
```

### iOS

Set `TgfxPrewarm` in `Info.plist`; no launch code needed.

```xml title="Info.plist"
<key>TgfxPrewarm</key>
<true/>
```

`TGFX_PREWARM=1` or `0` in the scheme overrides the key on local runs. To time it
yourself, leave the key out and call `prewarm`; Swift needs a bridging header.

```objc title="YourApp-Bridging-Header.h"
#import <NitroTgfx/TgfxPrewarm.h>
```

```swift title="AppDelegate.swift"
TgfxPrewarm.prewarm()
```

### What it buys

Samsung SM-E146B, four cold starts per arm:

| | without prewarm | with prewarm |
|---|---|---|
| `libNitroTgfx` load | 10 ms, on the main thread | 15–19 ms, on the render thread |
| first canvas window | 25.3 / 28.4 / 29.0 / 31.0 ms | 9.6 / 10.9 / 13.5 / 13.5 ms |

The first canvas window drops from **28.4 ms to 11.9 ms** on average.

## Keep it cheap

- Animate through `SharedValue` props or
  [`NodeHandle.set`](/api/interfaces/NodeHandle); changing JSX props re-uploads
  the scene.
- Keep children primitive; wrapper components take a slower path.

  ```tsx
  {/* fast */}
  <Canvas>{shapes.map((s) => <Rect key={s.id} {...s} />)}</Canvas>

  {/* falls back */}
  <Canvas>{shapes.map((s) => <Star key={s.id} {...s} />)}</Canvas>
  ```

- Group same-kind shapes as siblings.
- Adjacent `<Path>` siblings with the same solid paint draw as one batch. Keep
  the `path` string stable.
- `<Group picture>` records a static subtree once. Use `<Group layer>` only for
  group opacity or filters.
- Pool handles with [`createHandle`](/api/functions/createHandle) and toggle
  `visible` instead of remounting. Keep pools to hundreds of handles: on the
  SM-E146B each one costs about 0.6 ms to create, and writing 5,000 per
  frame stalls.
- For large sprite or mesh collections, use
  [`useSpriteBuffer`](/api/functions/useSpriteBuffer) or
  [`useVertexBuffer`](/api/functions/useVertexBuffer). A worklet writes
  positions straight into shared memory, with no per-node call.
- One animated opacity per chain ([Animation](/docs/animation)).
- [`purgeCaches`](/api/functions/purgeCaches) frees the image and GPU caches;
  [`getCacheInfo`](/api/functions/getCacheInfo) reports them
  ([Images § Cache](/docs/images#cache)).
