[`useNode`](/api/functions/useNode) returns a [`NodeHandle`](/api/interfaces/NodeHandle).
`set()` changes a mounted node without a React render. Slot-backed writes patch
in place and can run in a worklet; a prop without a slot re-encodes the scene on
the JS thread. Most non-geometry slot families are created lazily, so their
first write re-encodes once and later writes patch in place.

```tsx
import { Canvas, RoundedRect, useNode } from 'react-native-tgfx'

function Box() {
  const box = useNode()

  return (
    <>
      <Canvas style={{ width: 300, height: 200 }}>
        <RoundedRect ref={box} x={20} y={20} width={70} height={50} r={12} color="#4F8EF7" />
      </Canvas>
      <Button title="move" onPress={() => box.set({ x: 120 })} />
    </>
  )
}
```

## Colour from a worklet

```tsx
box.set({ color: '#4F8EF7' })         // JS thread only — the parser lives there
box.set({ color: 0xff4f8ef7 })        // packed AARRGGBB, worklet-safe
box.set({ color: [0.3, 0.5, 1, 1] })  // r, g, b, a in 0..1, worklet-safe
```

## Gestures

```tsx
const pan = Gesture.Pan().onUpdate((e) => {
  'worklet'
  dot.set({ cx: e.x, cy: e.y })
})
```

A node handle writes a value slot, which is worklet-safe. The canvas
[`viewport`](/docs/animation#zoom-and-pan) is not a slot — it sits above the
draw program entirely — but it has its own UI-thread path: pass a
`SharedValue<Viewport>` as the `viewport` prop and write it from the gesture
worklet.

```tsx
const viewport = useSharedValue({ zoom: 1, x: 0, y: 0 })
const zoom = Gesture.Pinch().onChange((e) => {
  const at = viewport.value
  viewport.value = { ...at, zoom: at.zoom * e.scaleChange }
})
// <Canvas viewport={viewport}>
```

`CanvasHandle.setViewport()` is the same write from the JS thread, for a
gesture running with `runOnJS(true)` or any other JS-side caller. Both cost
one native write per tick, with no React render and no scene re-encode.

## What has slots

Geometry, group transform operands, paint values and enums, image handles and
source rectangles, shader uniforms, gradient geometry and stops, blur and
shadow parameters, the alpha threshold, the backdrop material, the film grain's
size, density and seed, text and path strings, and `visible`. A handle keeps at most
16 gradient stops, so a longer imperative stop list is truncated. Its uniform
pool holds 32 floats; uniforms that do not fit fall back to re-encoding.

```tsx
fx.set({ uniforms: { uFace: [face.x, face.y], uRadius: face.width / 2 } })
label.set({ text: String(Math.round(fps.value)) })
sprite.set({ rect: { x: frame * 32, y: 0, width: 32, height: 32 } })
fade.set({ end: { x: drag.x, y: 0 }, positions: [0, t] })
glow.set({ blur: 4 + press.value * 12, dy: 2 + press.value * 6 })
```

## Pools

[`createHandle`](/api/functions/createHandle) is `useNode` without the hook, for
making N handles at once. `visible={false}` skips drawing and hit testing.

```tsx
const [dots] = useState(() => Array.from({ length: 64 }, () => createHandle()))

<Canvas>
  {dots.map((ref, i) => (
    <Circle key={i} ref={ref} cx={0} cy={0} r={4} visible={false} color="#fff" />
  ))}
</Canvas>

dots[next].set({ visible: true, cx: x, cy: y })
```

## Scenes without React

Every component has an element factory — a plain function returning the node
the JSX would: [`rect`](/api/functions/rect), [`circle`](/api/functions/circle),
[`group`](/api/functions/group), [`linearGradient`](/api/functions/linearGradient),
[`mask`](/api/functions/mask), and so on, one per component. A
[`Scene`](/api/classes/Scene) holds a tree of them, compiles it through the same
engine `<Canvas>` uses, and drives any attached target — no React anywhere.
The two forms compile byte-for-byte the same program:

```tsx
import { Canvas, Circle, Group, LinearGradient, Rect, useNode } from 'react-native-tgfx'

function Scene() {
  const box = useNode()
  return (
    <Canvas style={{ flex: 1 }}>
      <Rect ref={box} x={0} y={0} width={40} height={40} color="tomato" />
      <Circle cx={100} cy={100} r={20}>
        <LinearGradient start={{ x: 80, y: 80 }} end={{ x: 120, y: 120 }} colors={['#000', '#fff']} />
      </Circle>
      <Group transform={[{ rotate: 0.3 }]}>
        <Rect x={-20} y={-20} width={40} height={40} color="gold" />
      </Group>
    </Canvas>
  )
}

// later, from JS or a worklet — no React render
box.set({ x: 120 })
```

<Tab value="Imperative">

```ts
import { Scene, circle, createHandle, group, linearGradient, rect } from 'react-native-tgfx'

const box = createHandle()
const scene = Scene.create()
scene.add(rect({ ref: box, x: 0, y: 0, width: 40, height: 40, color: 'tomato' }))
scene.add(
  circle({ cx: 100, cy: 100, r: 20 }, [
    linearGradient({ start: { x: 80, y: 80 }, end: { x: 120, y: 120 }, colors: ['#000', '#fff'] }),
  ])
)
scene.add(
  group({ transform: [{ rotate: 0.3 }] }, [
    rect({ x: -20, y: -20, width: 40, height: 40, color: 'gold' }),
  ])
)

const detach = scene.attach(viewRef)   // a TgfxViewRef from <TgfxNativeView>

// later, from JS or a worklet — no re-encode
box.set({ x: 120 })
```

Structural mutations (`add`, `insert`, `remove`, `replaceChildren`) batch into
one compile per microtask — a 1000-add loop costs one encode — and `flush()`
commits now. Value mutation goes through handles, exactly as with JSX: do not
rebuild the tree per frame. One scene can drive several targets at once; each
gets the full program on attach and deltas after.

`ref` props, `SharedValue` props and worklet writes behave identically to their
JSX equivalents — the factories produce the very nodes the reconciler would.

## Where slot writes go

A handle's value slots live in one native memory block per handle, mapped into
every runtime — the same mechanism as its patchability flags. A `set()` write
is a plain store into that shared memory: nothing is serialized across
runtimes, so writing from the JS thread on a timer or per gesture frame
allocates nothing per write. (Routing these writes through Reanimated
SharedValues serialized a fresh worklet closure per write on the JS thread —
native heap the JS GCs never felt pressure to reclaim, growing ~10 MB/min at
60 Hz write rates.) A JS-thread write pushes the patched slots to the canvas
itself; a worklet-side write bumps the handle's wake value so the UI-thread
driver pushes on the next mapper run. Semantics are unchanged: last write wins,
and the next React commit is still the truth.

The whole scene can also be built *inside* a worklet — `createScene()` is
`Scene.create` as a plain function, which is the form that crosses runtimes —
see [Worklets](/docs/headless#worklets) for the rules.

## Buffers

[`useSpriteBuffer`](/api/functions/useSpriteBuffer) and
[`useVertexBuffer`](/api/functions/useVertexBuffer) share a typed array with the
renderer for counts too large for one handle each
([`SpriteBuffer`](/api/interfaces/SpriteBuffer), [`VertexBuffer`](/api/interfaces/VertexBuffer)).

```tsx
const sprites = useSpriteBuffer(512)   // SPRITE_FLOATS per sprite
const count = useSharedValue(0)

<Atlas image={sheet} buffer={sprites} count={count} />

// per frame, in a worklet: srcX, srcY, srcW, srcH, scale, centreX, centreY
sprites.set(i, 0, 0, 16, 16, p.scale, p.x, p.y)
count.value = alive                    // set the count after filling entries
```

`useVertexBuffer` takes a [`VertexBufferOptions`](/api/interfaces/VertexBufferOptions)
(`maxVertices`, optional `maxIndices`, and `textures`/`colors` to reserve those
sections). Its `positions`/`textures`/`colors`/`indices` are plain
`Float32Array` views, written directly from JS:

```tsx
const mesh = useVertexBuffer({ maxVertices: 4, maxIndices: 6 })
mesh.positions.set([0, 0, 200, 0, 0, 200, 200, 200])
mesh.indices.set([0, 1, 2, 1, 2, 3])

<Vertices buffer={mesh} vertexCount={4} indexCount={6} />
```

A worklet's captured `mesh.positions` is a cloned copy, not the shared memory —
call [`meshViews`](/api/functions/meshViews) there to map this runtime's own
view onto the same buffer:

```tsx
const drag = Gesture.Pan().onUpdate((e) => {
  'worklet'
  meshViews(mesh).positions[0] = e.x
})
```
